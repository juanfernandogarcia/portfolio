/* Build: Design Components -> site/
 * Usage: run from run_script (see chat). Regenerates every page in site/
 * from the .dc.html sources so the published site always matches the editor.
 *
 * Steps per page:
 *   1. drop every element marked data-editor-only
 *   2. drop the data-editor-hint attribute
 *   3. editor = true  ->  editor = false
 *   4. rewrite .dc.html links to the published .html names
 *   5. give every filled image slot src="media/<slug>/<slot-id>.<ext>"
 *      (portfolio-level images stay at media/<slot-id>.<ext>, no subfolder)
 *   6. bake the gallery order (localStorage is per-browser, the site needs it inline)
 *
 * The gallery order lives in gallery-order.json at the project root. Refresh it
 * from the editor before building, otherwise photos and videos publish in the
 * wrong order:
 *   eval_js_user_view -> localStorage['jfg-gal-order']
 *
 * Images from project 02 onwards are real files in media/<slug>/ referenced with
 * src on each image-slot, NOT entries in .image-slots.state.json. That sidecar
 * hit its ~2 MB write ceiling, so images dropped in the editor no longer persist
 * there.
 *
 * Videos are never part of a build. They are files the author pushes to
 * media/<slug>/ (p02-a-v1.mp4, p02-b-v1.mp4 ...). A build must never delete them:
 * copy the generated files over the repo, do not replace the media folder wholesale.
 */
